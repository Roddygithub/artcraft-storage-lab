Network debugging and rollback
  Initial callback attempts returned HTTP 500 because the callback worker in
  the synthetic Seahub container could not reach the Document Server URL at
  127.0.0.1:18088 from its own loopback. This was a test-network issue, not a
  successful save. The synthetic Seahub container was recreated with pasta
  --map-host-loopback=169.254.1.2, preserving its MySQL data, then a socat relay
  bound only to container loopback forwarded 127.0.0.1:18088 to the mapped host
  loopback. A health check through that path returned HTTP 200; subsequent
  callback POSTs returned HTTP 200 and both versions/readbacks were verified.
  Host port bindings remained loopback-only.

  Temporary ONLYOFFICE settings and the generated env file were removed after
  evidence capture. The running synthetic Document Server container retains
  its test-only environment configuration; the container is local and bound to
  loopback. The host mapping used by the synthetic container remains in place
  while that container runs. Production Seahub, ONLYOFFICE, settings, and files
  were untouched.

Limitations
