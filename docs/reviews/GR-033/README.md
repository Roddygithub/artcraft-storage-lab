# GR-033 PhotoCraft host protocol runtime smoke

## Scope

This is a local browser smoke harness for the Rust-only `?host=parent` adapter added in GR-032. It exercises one PhotoCraft `.pcraft` document, captures the adapter's exact save ticket and serialized bytes, acknowledges that ticket in memory, and offers a fresh iframe reload from the retained bytes. It does not connect to Seafile, dispatch to another editor, or test persistence beyond the browser page's memory.

## Browser run

1. Copy the built output to root `dist/web/` (ignored build output) and serve this repository root on port 8766 (commands below).
2. Open `/docs/reviews/GR-033/runtime/host.html`.
3. Click **Open synthetic .pcraft**. The parent waits for `photocraft:ready`, then transfers the fixture bytes with `photocraft:open`.
4. Make a visible edit in the PhotoCraft iframe (for example, Layer → New → Layer), then use File → Save.
5. Inspect the protocol log for `photocraft:save`, its ticket, serialized byte length, and SHA-256. Click **Send matching success ACK**.
6. Click **Open saved bytes in fresh editor**. The new iframe receives the captured save bytes and must show the added layer with `dirty=false`.

This run was performed in T3's Chromium preview on 2026-10-25 against `127.0.0.1:8766`. It used the actual PhotoCraft WASM app, a same-origin parent, and UI actions for layer creation and File → Save. The parent retained the save bytes in JavaScript memory; it did not write a file or call an external service.

## Evidence and limits

This establishes a real-browser, same-origin editor protocol smoke: open → UI edit → serialized save bytes → matching in-memory ACK → clean state → fresh iframe reopen from those bytes. It does **not** establish durable host storage, server-side version creation, gateway size behavior under an actual host, Seafile integration, or ONLYOFFICE non-regression. The harness requires a user-visible edit and browser File → Save action; no product JS/TS or dispatch code is added. The fixture and WASM bundle are not stored in Git; hashes and build instructions permit recreation.
